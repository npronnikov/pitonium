# Запуск и развёртывание ПИТОН V5

## Переносимая версия: Node 24 и SQLite

Используйте архив PITON_V5 с собственными `package.json` и `package-lock.json`. Node.js 24 требуется для штатного `node:sqlite` и online backup API. Установка фиксирована lockfile:

```bash
npm ci
npm run typecheck
npm test
npm run build
npm start
```

`npm run build` выполняет структурную проверку контента, затем собирает Vite frontend в `dist/standalone` и SSR bundle API в `dist/api/server.mjs`. Команда `npm start` запускает один Node-процесс, который обслуживает оба. База создаётся и мигрируется автоматически. Production-процесс не использует TSX; операторские команды и разработка используют TSX, поэтому сохраняйте devDependencies для этих операций.

Для разработки достаточно `npm run dev`: интерфейс слушает `127.0.0.1:5173`, API — `127.0.0.1:8787`, `/api` проксируется. Скрипт управляет обоими дочерними процессами и завершает их совместно. Порты development в этом скрипте фиксированы.

## Конфигурация локального сервера

Скопируйте `.env.example` в `.env`. Запуск с этим файлом явный:

```bash
node --env-file=.env dist/api/server.mjs
```

| Переменная | Значение по умолчанию / назначение |
| --- | --- |
| `HOST` | `127.0.0.1`, сетевой адрес прослушивания |
| `PORT` | `8787` |
| `PITON_PUBLIC_ORIGIN` | `http://localhost:8787`, внешний origin приложения |
| `PITON_ALLOWED_ORIGINS` | Дополнительные origin через запятую |
| `PITON_DB_PATH` | `data/piton.sqlite`, относительно рабочего каталога |
| `PITON_STATIC_DIR` | `dist/standalone`, относительно рабочего каталога |
| `PITON_TIME_ZONE` | `UTC`, календарные дни прогресса |
| `TUTOR_ENDPOINT` | HTTPS endpoint протокола chat completions; пусто — подготовленные подсказки |
| `TUTOR_API_KEY` | Секрет только серверу |
| `TUTOR_MODEL` | Идентификатор модели выбранного оператором провайдера |

При размещении за reverse proxy укажите фактический HTTPS origin и сохраняйте соответствующий Host. Отдельно настройте HTTPS, управление процессом и долговечный том для каталога данных. Локальный сервер намеренно проверяет Host и Origin: неизвестный Host возвращает 400, неподходящий Origin записи — 403. Сам Node endpoint не завершает TLS. `cookieSecure` зависит от внешнего origin.

Не включайте `data`, `.env`, резервные копии или реальные секреты в исходный архив. Пользовательские данные живут отдельно от приложения. Pyodide загружается браузером с фиксированного CDN; это не полностью автономная офлайн-поставка. При изменении родительского CSP обязательно повторите реальный запуск Python в браузере: sandbox использует iframe srcdoc, blob worker и предварительную загрузку runtime.

## Миграции и резервная копия

Штатные SQL-миграции находятся в `drizzle/`, их порядок — в `drizzle/meta/_journal.json`. Node API применяет отсутствующие миграции до начала обслуживания. Повторное применение уже учтённой миграции не требуется.

```bash
npm run db:migrate
npm run db:check
npm run db:backup -- --to backups/piton-2026-10-18.sqlite
npm run db:restore -- --from backups/piton-2026-10-18.sqlite --db data/recovered.sqlite
```

`db:backup` использует online backup SQLite и публикует готовый файл атомарно. `db:restore` проверяет входную базу и по умолчанию восстанавливает только в новый путь. При замене рабочей базы сначала остановите API; `--force` — явное разрешение заменить уже существующий файл. Активный writer защищён lock-файлом. После восстановления выполните `db:check` с тем же `--db`.

Миграция существующей базы V4 в эту поставку не включена: исходная база и её схема не были предоставлены. Не подставляйте неизвестную старую базу вместо V5 без сопоставления схем и резервной копии.

## Размещение через Sites

Главный checkout содержит `app`, `build`, `.openai/hosting.json` и корневой pnpm lock. В нём `build` собирает Worker для Sites, а `build:local` — локальный Node-вариант. Для размещения используйте штатные средства Sites: они сохраняют source commit, собирают и пакуют именно эту ревизию, применяют D1 migrations и развёртывают сохранённую версию.

Binding базы объявлен как `DB`. Hosted route использует `createD1Adapter` и проверенную платформой личность через `getChatGPTUser`. Для размещённого приватного проекта доступ определяется политикой платформы; приложение не реализует собственную копию её зарезервированных маршрутов входа. Не направляйте локальные SQLite-команды на D1.

Если нужен внешний AI-provider, задайте три `TUTOR_*` переменные в серверной конфигурации размещения. Никакие `VITE_*` или клиентские переменные для ключей не используются. Без конфигурации доступны все четыре уровня подготовленных подсказок.

Проверяйте терминальный статус deployment перед передачей ссылки. Сборка, SSR и тесты API не доказывают работу итоговых браузерных заголовков. После первого открытия размещённой версии следует пройти сценарии из `QA_REPORT.md`, включая старт Pyodide и смену профиля во время запуска.

## Создание обновлённой npm-поставки

Из основного checkout выполните:

```bash
node scripts/export-portable.mjs --output /absolute/path/to/PITON_V5
```

Экспорт не изменяет корневой pnpm manifest. Шаблоны npm и проверенный lock лежат в `distribution/`; exporter проверяет их соответствие, копирует application source, тесты, документацию и всю графику. Папка назначения должна быть новой или пустой. Затем в ней выполняются `npm ci`, `npm run typecheck` и `npm run build`; установленный `node_modules` и пользовательская база не требуются в распространяемом ZIP.
