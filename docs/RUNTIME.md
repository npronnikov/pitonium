# Исполнитель Python в PITON V5

## Что реализовано

Уроки исполняются настоящим **Pyodide 314.0.7 / CPython 3.14**, без распознавания «правильного» исходного текста и без имитации вывода. Один и тот же протокол обслуживает детскую сцену с роботом, подростковую арену и взрослые задачи с функциями, входными строками и файлами.

Клиентский вход — `packages/runtime/index.ts`. Он экспортирует `createPythonRunner()`, типы, Zod-схемы, `defaultLimits` и `runtimeVersion = 'pyodide-314.0.7'`. Для автоматических тестов существует отдельный `packages/runtime/node.ts`; его нельзя подключать к клиентскому бандлу или использовать как серверный sandbox для чужого кода.

```ts
import { createPythonRunner, type RunRequest } from '../packages/runtime';

const runner = createPythonRunner({
  isContextCurrent: context =>
    context.profileId === activeProfile.id &&
    context.draftVersion === draft.version &&
    context.variantId === activeVariant.id,
});

const request: RunRequest = {
  protocolVersion: '1',
  runId: crypto.randomUUID(),
  context: {
    profileId: activeProfile.id,
    lessonId: lesson.id,
    variantId: activeVariant.id,
    draftVersion: draft.version,
    testsVersion: lesson.assessmentVersion,
  },
  operation: 'check',
  code: draft.code,
  preview: activeVariant.preview,
  tests: activeVariant.tests,
};

const result = await runner.run(request, progress => setRuntimeProgress(progress));
// Сохранение и награды обрабатывает API приложения после проверки контекста.
// При смене профиля, урока или режима:
runner.cancel();
// При размонтировании страницы:
runner.dispose();
```

Функцию `isContextCurrent` следует связывать с актуальными ссылками на состояние, чтобы замыкание не сохраняло предыдущий профиль. Runtime проверяет её перед запуском, после выполнения каждого случая и перед выдачей результата. Начало нового запуска автоматически отменяет предыдущий. Отменённый, устаревший или завершившийся по тайм-ауту запуск не становится успешной проверкой.

## Протокол и оценивание

`RunRequest` содержит исходный код, контекст, один случай для предпросмотра и массив тестовых случаев. Контекст включает `profileId`, `lessonId`, `variantId`, `draftVersion` и `testsVersion`. Перед созданием Worker запрос проходит строгую Zod-проверку: неизвестные поля, некорректные пути, повторяющиеся идентификаторы тестов, чрезмерные лимиты и слишком большой запрос отклоняются.

`operation: 'preview'` выполняет только случай предпросмотра. `operation: 'check'` сначала выполняет предпросмотр, затем каждый тест в новом Worker. Это сохраняет сцену текущего задания на экране и одновременно проверяет другие входные данные. Между случаями не переносятся Python-глобальные переменные, импортированные учеником модули или созданные файлы.

`ExecutionCase` имеет два обязательных поля:

| Поле | Назначение |
|---|---|
| `fixtures` | Входные глобальные переменные, строки для `input()`, UTF-8 файлы и сцена; без данных передаётся `{}`. |
| `probe` | `{ kind: 'script' }` запускает программу; `{ kind: 'call', functionName, args }` после запуска вызывает указанную Python-функцию с аргументами JSON. |

`TestCase` дополнительно содержит `id`, `label`, `assertions`. Поддерживаются проверки статуса и типа ошибки, возвращаемого значения, stdout, последовательности или количества событий, позиции робота и содержимого файла. Объекты сравниваются по значениям независимо от порядка ключей; списки сохраняют порядок. Имена локальных переменных и способ решения не влияют на оценку.

`RunResult` возвращает `stdout`, `stderr`, `error`, игровые `events`, настоящий построчный `trace`, `testResults`, UTF-8 `dataFiles`, при наличии — `returnValue`, а также статус, контекст, версию runtime и признаки усечения. Во время работы callback получает фазы `loading`, `executing`, `checking`, `complete`.

**Статус выполнения и результат проверки — разные поля.** `status: 'ok'` означает, что Python выполнился без ошибки. Неверное возвращаемое число при этом даёт `testResults[i].passed: false`. Неожиданная Python-ошибка всегда делает тест неуспешным, даже когда число событий совпало с ожидаемым. Для будущих задач с ожидаемой ошибкой существует `statusEquals` с `errorType`; проверяется и конкретный тип ошибки.

В P0 результат имеет `gradingAuthority: 'browser-preview'`. Тесты и результат доступны клиенту, поэтому эта версия **не предоставляет защищённое от подделки оценивание**. Сервер обязан проверять владельца профиля, версии контента и тестов, текущий урок и вариант, точный набор идентификаторов тестов, отсутствие дубликатов и идемпотентность записи. XP рассчитывается сервером; команды сцены и клиентское число XP не являются основанием для награды. Для защищённых экзаменов потребуется отдельный серверный grader.

## Проверяемые задачи P0

### Робот: количество шагов задаёт входная переменная

Предпросмотр предоставляет `steps = 5`. Проверки независимо предоставляют `0`, `1`, `5`; ширина поля равна `steps + 1`, старт — `(0, 0)`, цель — `(steps, 0)`.

```python
for robot_step in range(steps):
    game.move(1)
```

Проверяется успешное завершение, точное число `actor.move` и конечная позиция. `range(5)` проваливает случаи `0` и `1`. Попытка шестого шага в сцене на пять шагов вызывает `GameBlocked`: пять уже записанных событий не скрывают ошибку. Другое корректное решение, например цикл `while` с обратным отсчётом, проходит поведенческие проверки.

### Арена: параметр функции определяет волну

```python
def spawn_wave(n):
    for enemy_number in range(n):
        game.spawn('slime', x=80 + enemy_number * 80, y=160)
```

Функция вызывается с `n = 0`, `1`, `5`; события учитывают и действия верхнего уровня программы, и действия внутри вызова. `x` и `y` поддерживают именованные аргументы. API проверяет допустимый вид врага, границы арены и предел количества врагов.

### Отчёт: пустые данные, обычные строки, возвраты

`build_report(items)` принимает строки `{name, amount}` и возвращает `{total, count, rows}`. Проверки включают пустой список, обычные значения, ноль и отрицательную сумму возврата. Возвращаемые строки должны сохранять содержание и порядок. Проверяется реальное JSON-значение, а не напечатанная строка.

Файловые задачи получают данные через `fixtures.files`. Например, `shopping_list('shopping.txt')` читает настоящий файл внутри виртуальной файловой системы и возвращает непустые строки после `strip()`. Созданные в рабочей папке текстовые файлы возвращаются в `dataFiles` и могут проверяться через `fileEquals`.

## Игровой мост

Python получает учебный модуль `game` и несколько удобных алиасов. Он выдаёт только данные для отображения; модуль не получает DOM, профиль, токены, клиент API или функции сохранения.

| Python API | Событие |
|---|---|
| `game.move(steps=1)` / `move()` | По одному `actor.move` на пройденную клетку |
| `game.turn('left' / 'right' / 'back')` | `actor.turn` с итоговым направлением |
| `game.say(text)` / `say(text)` | `actor.say` |
| `game.collect(item_id='star')` | `item.collect` |
| `game.spawn(kind, x=0, y=0)` / `spawn_enemy(...)` | `enemy.spawn` |
| `game.score(value)` | `score.update`, локальный счёт сцены |
| `game.open_gate(gate_id='gate')` | `gate.open` |
| `game.complete()` | `scene.complete`; само событие не означает сдачу урока |

Все события после получения проверяются `gameEventSchema`: разрешены только восемь типов, строгие поля и payload, ограниченные числа и идентификаторы. HTML и URL в игровых репликах отклоняются. Индексы должны идти подряд с `1`. JSON Schema для внешних потребителей находится в `packages/contracts/scene-events.schema.json`.

## Граница браузерного исполнения

1. Доверенный код страницы загружает **пять фиксированных файлов** версии `314.0.7`: два ES-модуля, WebAssembly, архив стандартной библиотеки и lock-файл. Запросы не содержат cookie или данные ученика. Исходный код не задаёт URL загрузки.
2. Создаётся скрытый iframe с единственным флагом `sandbox="allow-scripts"`. `allow-same-origin` отсутствует, поэтому у iframe отдельный opaque origin.
3. CSP разрешает скрипт контроллера по случайному nonce, локальные `blob:` модули и компиляцию WASM. `connect-src blob:` не разрешает HTTP, WebSocket или обращение к API приложения. Формы, вложенные страницы, изображения и объекты запрещены.
4. Handshake проверяет одновременно `event.source === iframe.contentWindow` и непредсказуемый nonce. Одна строка origin `"null"` не считается подтверждением отправителя. После handshake используется выделенный `MessageChannel`.
5. Контроллер создаёт новый **module Worker** из blob для каждого случая. Worker получает только байты runtime, доверенный harness и `{code, case, limits}`. Контекст профиля остаётся в родительской странице.
6. Pyodide получает пустой `jsglobals`. Внутренние загрузки фиксированных WASM/stdlib URL обслуживаются из уже переданных байтов и не переадресуются в сеть. Это нужно потому, что версия `314.0.7` начинает подготовку WASM-загрузки до вызова переданного `createPyodideModule`.
7. Контроллер и родительская страница имеют независимые таймеры. Отмена или тайм-аут завершают Worker; завершение операции удаляет iframe, закрывает порт и освобождает его ресурсы. Следующий запуск получает новый исполнитель.

Перехват Python `__import__` и `open` помогает ученику работать с явным API и файлами задания. **Эти перехваты не являются sandbox.** Граница клиентской версии состоит из origin isolation, CSP, отсутствия привилегированных мостов и принудительного завершения Worker. Код, рассчитанный на взлом Python-harness или подделку клиентской оценки, нельзя считать безопасно оценённым сервером.

Браузерный runtime не монтирует диск пользователя. Файлы создаются в `/piton/workspace` внутри MEMFS конкретного Pyodide. Вне рабочей папки присутствуют системные файлы самого Python; строгая защита их содержимого от целенаправленного вмешательства не заявляется. Системные файлы не содержат данные приложения или пользователя.

## Лимиты и восстановление

| Лимит по умолчанию | Значение |
|---|---:|
| Выполнение одного случая | 3 000 мс |
| Начальная загрузка | 45 000 мс |
| stdout и stderr, каждый | 32 768 байт |
| Игровые события | 512 |
| Снимки трассы | 200 |
| Данные трассы | 131 072 байт |
| Экспортируемые UTF-8 файлы | 262 144 байт суммарно, до 32 файлов |

Бюджеты вывода, трассы и файлов учитывают UTF-8 байты; получатель также сверяет фактические размеры. Трасса содержит номера выполняемых строк и ограниченные снимки простых локальных значений. Имена, содержащие `password`, `token`, `secret`, `email`, скрываются; это удобство отображения, а не способ передавать секреты в ученический процесс.

Линейный Python tracer помогает быстро выявить бесконечный цикл, но окончательное ограничение времени обеспечивает внешний таймер Worker. Тест с `sys.settrace(None)` подтверждает, что отключение tracer не отключает принудительную остановку. Для отмены не требуются SharedArrayBuffer, COOP или COEP.

Жёсткая квота всей WASM-памяти и защита от исчерпания ресурсов вкладки в этой версии не гарантируются. Разрешённый вход ограничен, но намеренная огромная Python-аллокация может потребовать больше памяти до остановки Worker. Для production grader нужны отдельные процессы с ограничением памяти/CPU, отсутствием сети и секретов, закрытыми тестами и независимым подсчётом результата.

## Выполненная проверка и её пределы

```sh
node --import tsx --test tests/runtime*.test.ts
node --experimental-vm-modules packages/runtime/verify-preloaded-runtime.mjs
npx tsc --noEmit
```

`runtime.test.ts` исполняет настоящий Pyodide в Node Workers. Сценарии проверяют три режима P0, альтернативное решение, hardcode и лишний шаг, отличие статуса от успешности теста, stdin и UTF-8 файлы, чистое состояние, Python-ошибки и номера строк, отмену, принудительный тайм-аут, повторный запуск, смену профиля, перекрывающиеся запуски, лимиты и явные учебные API.

`runtime-protocol.test.ts` проверяет строгий whitelist, инварианты оценивания и недопустимые запросы. Проверки строк CSP и параметров iframe предотвращают регрессии конфигурации, но не доказывают поведение браузера.

`runtime-bootstrap.test.ts` запускает **исходный browser Worker** с настоящими distribution-файлами Pyodide в Node VM: разрешены WASM и локальные blob-модули, запрещена компиляция JS-строк, отсутствует реализация внешнего HTTP fetch. Smoke-тест подтверждает загрузку, пять игровых движений и вывод `42` без внешней сети. Это отдельная проверка совместимости загрузчика; VM не является моделью browser origin isolation.

**Браузерная проверка iframe/CSP/MessageChannel в этой рабочей сессии не выполнялась**, потому что доступного Browser skill для разрешённого workflow нет. Перед выпуском для пользователей остаётся проверить фактический запуск, сетевую изоляцию и восстановление после остановки в поддерживаемых браузерах. Автоматические Node-тесты не подменяют этот этап.
